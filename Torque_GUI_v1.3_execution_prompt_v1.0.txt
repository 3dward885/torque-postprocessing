2. IMPLEMENT THE SEVEN REQUESTED CHANGES

A. Clear temperature-field labels

Rename the general list:
  Temperatures in this file (K)
Rename the optional selected-scan assignment:
  Override selected scan temperature (K)

Preserve scope and precedence. The general list supplies experimental setpoints
for the file; each scan needs a unique match within its configured tolerance.
An explicit override applies only to the selected scan(s). Leaving the override
blank preserves existing explicit assignments. Explain this briefly in help.
Do not turn the general list into one temperature applied to every scan.

B. Flexible temperature-list entry

Accept whitespace-separated, comma-separated and mixed temperature lists,
including decimal values, using one small shared parser for GUI and CLI input.
For example, these must represent the same user settings:
  2.5 5 10 25 50 100 150 200 250
  2.5, 5, 10, 25, 50, 100, 150, 200, 250

Retain Decimal semantics and existing invalid/nonfinite/duplicate-value checks.
Preserve blank-list/missing-assignment behavior and saved configuration lists.
Use a concise hint such as “Separate values with spaces or commas”.
Document quoting of a whitespace list in the CLI. Do not hardcode experimental
temperature targets, broaden tolerances or add a fallback temperature grid.

C. Plot selection must agree with the displayed data

Currently, changing settings can clear processed results while the View box
still says Corrected and the graph displays raw torque. Fix this inconsistency.

initial import, background scans, scan/file changes, partial processing, failures,

mislabeling or substituting data. Retain a sensible selection when still valid.

G. Optional uniform sample-position correction

Add a file-level “Apply sample-position correction” checkbox, unchecked by
default. When checked, reveal:
  Correction value (deg)
  Add (+) / Subtract (−)

The magnitude must be finite and nonnegative. Zero is valid; reject a negative
magnitude because direction is selected separately. When unchecked, use no
correction, regardless of retained inactive values. Do not apply one file's
setting to other loaded files without explicit user action.

Define the signed correction d:
  Add:      d = +magnitude_deg
  Subtract: d = -magnitude_deg
  corrected measured position = original measured position + d

Apply this same d once to every acquired row in that raw dataset, including all
signal and background scans, regardless of T, B or position. Always calculate
from immutable original positions; never accumulate shifts on reprocess.
No per-scan offset, automatic calibration, angle normalization, wrapping,
interpolation, regridding or inferred magnitude is authorized.

No actual probe-error magnitude has been supplied. This does not block feature
implementation. Use synthetic examples for nonzero corrections; do not claim
any example value is a measured correction for the supplied sample.

Coordinate integration is essential:
- Preserve raw files, original position tokens, measured torque, source-row
  identities and acquisition order. Keep original measured, corrected measured
  and processing/nominal coordinates distinguishable in the existing ledger.
- Preserve the established nominal-angle method. Conceptually, if theta_nom is
  the existing validated nominal coordinate, use theta_nom + d for processing.
  An equivalent implementation may validate corrected measured positions against
  the original grid shifted by d. Do not snap a corrected angle back onto the
  unshifted grid, thereby removing the correction or causing false deviations.
- Preserve angular deviation tolerances. Translate the reference and measurement
  consistently; a known constant coordinate correction does not widen tolerance.
  Use Decimal settings/token arithmetic through coordinate construction and
  comparisons, then the existing binary64 numerical core without extra rounding.
- Apply angle-range selection in the corrected nominal coordinate system before
  fitting and centering. The bounds mean corrected positions when enabled.
  Recompute actual retained rows and describe any changed membership.
- Fit backgrounds and evaluate signals at consistently corrected nominal angles.
  Retain the degree-six polynomial and its [0,200] scaling domain; that domain
  defines the numerical basis, not the admissible acquisition range.
- Use corrected coordinates consistently for coverage, processed plots and
  treated DAT. Keep Raw as the original measured-coordinate view and label the
  distinction clearly. Do not alter source scan identity because its coordinates
  were translated.
- A common shift does not itself expand background support relative to signals.
  Re-evaluate coverage after range selection and preserve explicit extrapolation
  requirements. Do not silently extrapolate or discard newly unsupported points.
- A changed effective correction requires reprocessing and validation of saved
  torque-baseline bindings. Preserve dirty-editor protections and block stale
  exports.

Persist enabled state, magnitude, operation, units, effective signed offset and
user-provided origin in shared GUI/CLI settings and existing provenance. Keep
lossless decimal settings and check redundant values if stored. The correction
is a user setting, not a discovered calibration constant. Distinguish position

Old configurations must load with correction disabled. Disabled and zero

3. PRESERVE THE NUMERICAL AND REPLAY CONTRACT

Keep the existing order after corrected-coordinate selection:
1. Quantize original retained signal/background torque tokens to six significant
   digits using the verified Decimal semantics.
2. Fit actual retained background samples with the unweighted degree-six model.
3. Evaluate at retained signal angles and subtract to obtain immutable u.
4. Apply the ordinary centering or the committed manual torque baseline once.
5. Serialize torque in N m with the existing binary64 .8g behavior.

For ordinary midrange:
  c_mid = (min(u) + max(u)) / 2
For accepted manual adjustment:
  c_final = c_mid + delta
  treated torque = u - c_final

Use all retained points, never the plot zoom window. Preserve mean policies
already chosen in saved configurations, per-scan Apply/Cancel/Reset/Remove,
nonaccumulation, constant-data handling and pan/zoom behavior.
No molar conversion, smoothing, averaging, synthetic points or reference-derived
correction. Output remains four columns: temperature (K), field (T), sample
position (deg), treated torque (N m). Explain corrected/nominal coordinates in
the existing metadata; retain original measurements in the ledger.

Use one shared processing/configuration path for GUI and CLI. Version and
migrate changed schemas explicitly; continue rejecting unknown versions and
invalid records. Include effective position correction and coordinate policy
in upstream identity. Exclude tooltip/help/view choices from numerical identity.
Retain lossless torque-offset representation and recomputed-u digest checks.

Never rewrite an accepted record's binding merely to make it validate. Preserve
valid older settings; if existing source/environment binding makes a v1.2 manual

Preserve same-file/rotation and experimental-temperature background associations,
