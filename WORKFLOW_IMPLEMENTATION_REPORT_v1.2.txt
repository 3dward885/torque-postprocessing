CHANGES
Temperature checks now compare each scan with supplied experimental setpoints, not an integer-K grid. The original absolute-deviation arithmetic was correct; the inferred 2 K reference was inappropriate for the user-confirmed 2.5 K condition. The 0.2 K tolerance remains configurable. No experimental T targets are built into production code.
Raw reading preserves all supported measurements before scan validation. The existing CSV/TSV schemas remain supported. Angular sweeps are identified in acquisition order, with explicit source-row starts available for ambiguous cases. Nominal angle/field treatment is retained without the former 0–200 degree admission restriction.
The main GUI provides Open data, Subtract background, Center zero and Save treated data. Raw preview appears on import; acquisition settings, angular bounds, background assignment and diagnostics are available without molar fields or header-format choices.
An optional inclusive angular interval is applied to actual signal and background rows before fitting, centering and export. Excluded endpoint torque values cannot bias the retained fit or midrange zero. No automatic anomaly detection, smoothing, averaging or fabricated points were introduced. Bounds use nominal angle coordinates; original measured angles remain in the ledger.
Molar conversion was removed from GUI/CLI/core/export. Four-column torque-only output and its details folder use existing transactional run export. Old molar settings migrate with a notice; obsolete new options fail explicitly.
Baseline schema 2 preserves per-scan accepted offsets and independent active IDs. Applying one scan does not activate another retained inactive setting. Range changes invalidate upstream bindings; dirty drafts block navigation/save. UI-thread image disposal fixes Tk cleanup during background work.
