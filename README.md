## Fixed-field review in v1.6

In Acquisition settings, choose **Fixed field** and enter **Review at field change (T)**. There is no experimental default. New and older sessions require this configuration; the old monotonic parser profile does not establish changing-field intent.

The check uses every original measured field in the acquired scan, before angle filtering: maximum minus minimum, with Oe converted to T using Decimal arithmetic. Round that span to 0.01 T (nearest, ties away from zero), then require review **at or above** the entered limit. For the user-approved example limit 0.50 T, a measured span of 0.499968148 T rounds to 0.50 T and triggers review; the effective unrounded boundary is 0.495 T. Original measurements, nominal field rounding, setpoint checks and the 1 Oe coordinate tolerance are unchanged.

A persistent warning and per-scan status identify unresolved scans. **Review scan** shows the measured minimum/maximum/span, policy, original source rows and field trace. This establishes a recorded change, not independent physical magnet verification. Closing the panel excludes nothing. Enter a reason to **Exclude entire scan** or **Permit changing field**. Alternatively correct erroneous acquisition settings. No automatic exclusion or stable-tail salvage occurs. Background acquisitions are checked too; excluded/unresolved backgrounds cannot supply a fit.

Final data and figure exports are blocked while any included scan is unresolved. Unaffected scans can still be processed and inspected. Exclusion removes the entire acquisition from treated outputs, while preserving all original rows and reasons in the adjacent audit data. Review decisions bind to source hash, acquisition identity, original field evidence and policy. Source/policy changes require review again; display and molar changes do not. Numerical recipe and accepted-baseline schemas remain unchanged. The optional `field_quality` configuration block has schema version 1.

After resolving reviews, save a **new** settings session and replay it normally:

```powershell
.\.venv\Scripts\python.exe app.py
.\.venv\Scripts\python.exe cli.py process --session "C:\path\reviewed_settings.json" --dat "C:\path\new_treated.dat"

```

For new CLI processing, `--field-condition fixed --field-review-limit "0.50"` records explicit inputs (0.50 is this user's setting, not an application default). `--field-condition changing` explicitly permits an intended changing-field experiment. Session replay uses its saved policy and decisions. Unresolved reviews return a nonzero exit code and identify affected scans.

## Process a file

1. **Open data…** loads the raw DAT and shows a raw preview.
2. In **Acquisition settings…**, enter the experimental temperature setpoints,
   separated by spaces, commas, or both. These are experiment settings, not values embedded in
   the program. Multiple scans can share a setpoint. A scan is assigned
   automatically only when all its temperatures match exactly one supplied
   setpoint within the allowed deviation. Use **Override selected scan temperature (K)** to
   resolve ambiguity for highlighted scans only. The general list is labelled
   **Temperatures in this file (K)**. A blank override preserves saved assignments. The current temperature deviation is 0.2 K; it is editable.
3. Optionally use **Angle range…**. Blank bounds retain all angles. Bounds such
   as 0 and 200 select the inclusive interval in the pipeline's nominal-angle
   coordinates. This interval applies to **background fitting, zero centering,
   processed previews and treated output**. Original measured angles remain in
   the row ledger. No points are interpolated or fabricated.
4. Check the selected background, then click **Subtract background**. Backgrounds
   must come from the same input and experimental temperature. A background
   acquired afterward is supported. Multiple candidates require a selection.
   Background coverage problems appear on the affected scans; other scans can
   still be reviewed. **Allow background extrapolation** is an explicit choice
   for the selected signal/background pair.
   Subtraction also applies the saved automatic centering policy: midrange by
   default, or mean when explicitly selected.
5. Optionally, **Center zero…** opens the selected signal scan. Drag the baseline or enter an
   offset from its midrange. **Apply** saves that scan's adjustment; **Cancel**
   discards the draft; **Reset** creates a zero-offset draft requiring Apply;
   **Remove override** restores ordinary centering. Dirty drafts must be applied
   or cancelled before navigation, settings changes or saving.
6. Use the main **Output** section to choose Torque or optional Molar torque,
   then save the selected data/plots as described below. Ordinary data remains
   four columns: K, T, degrees, N m, with its adjacent details folder.

Save/load settings and figure export are in the menus. Files and results are
independent. Settings can be applied to several selected scans using Ctrl/Shift
selection. The scan list reports retained/acquired point counts. To change a
previous explicit per-scan setpoint, enter the replacement for those selected
scans; changing the general setpoint list does not erase explicit assignments.

Existing output files are never overwritten. Unresolved scans and stale active
adjustments block saving; explicit exclusions are available in acquisition
settings and recorded in the ledger.

## Output quantity, data and plots

The main **Output** section belongs to the selected file. **Torque (N m)** is
the default. **Save torque data** saves the ordinary four-column DAT;
**Save torque plots** saves grouped JPEGs.

For molar output:

1. Choose **Molar torque (N m/mol)**.
2. Enter **Sample mass (mg)** and **Molar mass (g/mol)**, or select
   **Amount in moles** and enter **Amount (mol)**.
3. Check **Calculated amount**, then **Apply**.
4. Use **Save both data files** for ordinary N m and separate N m/mol DATs.
   The save window shows both filenames before writing; Browse selects the
   ordinary filename and the molar companion updates automatically.
   Use **Save molar plots** for JPEGs only.

Molar mass alone cannot determine sample amount:
`n = mass_mg / (1000 * molar_mass_g_mol)`;
`molar_torque = treated_torque / n`.
Mass and molar mass must refer to the same chemical basis. Nothing is inferred
from compound names or filenames. A positive but physically incorrect mass
cannot be detected automatically; check units and the calculated amount.

Sample changes are drafts until Apply. Cancel restores the committed values.
Apply or Cancel before changing files/quantity or saving. Invalid inputs show
an inline explanation. Each file has independent values. Switching clean settings
to Torque retains inactive sample entries. Decimal/scientific notation is accepted.

Corrected preview and its PDF/PNG export use the selected quantity. Raw,
Background fit, Processing steps and Center zero retain N m. Changing sample
quantities never refits, recenters or modifies the underlying treated torque.
The factor uses the existing 50-digit Decimal calculation; each molar value is
the exact Decimal product of that factor and the serialized N m torque token.
The read-only amount is rounded for display only.

Data and plots share the main Output settings. The plot dialog selects files
and rotation labels, and shows effective units/amount read-only. It saves
JPEGs and details only, with no incidental DAT. To export both plot quantities,
switch clean output mode and save each in a new folder. Batch files keep their
individual choices.

JPEGs are 8 x 6 inches, 2400 x 1800 pixels at 300 dpi, Arial Regular, white,
experimental markers only. Text is limited to rotation/temperature heading,
axis labels/ticks and field legend. No fitted/connecting curves or added
sample-quantity annotations. Background scans are excluded; distinct acquired
scans and files are not averaged or merged.

**Save settings** retains committed output choices in an optional version-1
`output` block beside each file's scientific `settings`. Processing configuration
1.2 and baseline schema 2 are unchanged. Old sessions open in Torque mode with
blank sample quantities. Legacy molar processing options remain obsolete.

The ordinary DAT's `.dat.details` folder contains the scientific settings, raw
snapshot, ledger and provenance, plus `output.json` and `replay.json`.
Keep that folder with both DATs. The latter session reproduces the selected output:
a Torque/old session saves ordinary DAT; a Molar session saves both DATs.
Input hashes must match. Unknown output versions or active invalid quantities
fail explicitly; output preferences do not change numerical baseline bindings.

No actual sample mass, molar mass or amount has been supplied for Ho2sq3.
Molar validation examples are explicitly synthetic software fixtures.

## Scientific method and v1.2 import correction

The previous import failure came from selecting a reference on a fixed 1 K grid.
For the user's 2.5 K setting, 2.49238 K differs by 0.00762 K and passes a 0.2 K
check. The former 2 K reference differed by 0.49238 K. Comparison arithmetic
was not the fault. Temperature targets now come from saved user settings or
explicit metadata; there is no fixed temperature list or fallback rounding.

The instrument schema's `User Temperature` field is not treated as a setpoint.
The supplied Ho2sq3 file has no explicit setpoint metadata. A documented optional
header record `INFO,"t1;t2;...",TEMPERATURE_SETPOINTS_K` can supply setpoints for
other files; explicit user settings take precedence, with conflicts recorded.

The numerical method remains: six-significant-digit Decimal torque tokens;
unweighted degree-six background polynomial on the existing [0,200] scaled
basis; evaluate at retained nominal signal angles; subtract; center once;
serialize torque with binary64 `.8g`. The scaling domain does not restrict
the acquisition's angular span. Angular and field tolerances remain configurable
under More acquisition settings. Measured source tokens are preserved separately
from the nominal coordinates used for fitting and export.

The optional angle interval selects actual rows before fitting and centering.
Thus excluded endpoint artifacts cannot influence the fitted background or
the retained-vector midrange. For retained background-subtracted torque u:
`c_mid = (min(u)+max(u))/2`, `c_final = c_mid + delta`,
`treated torque = u - c_final`. Positive delta shifts corrected torque downward.
This defines the selected data's midrange zero; it is not an independent absolute
torque calibration. No automatic anomaly detector or inferred point removal is used.

A range or upstream-data change requires reprocessing and invalidates affected
accepted offsets. Dragging uses cached immutable data, never rereads/refits, and
does not accumulate shifts. Saved offsets use exact hexadecimal binary64 values
plus checked readable values. Baseline schema 2 adds independent active scan IDs,
so applying one adjustment does not activate another retained inactive setting.
Schema 1 remains readable and undergoes normal binding checks.

Supported raw layouts: the documented 32-column instrument CSV header with
14–32 recorded fields, and the documented four-column TSV in K/Oe/deg/Nm.
The importer is not a universal DAT reader. Automatic scan boundaries follow
angular sweep restarts/reversals; ambiguous short scans require explicit source
row starts. Finite-value, unit, ordering, fit-rank and coverage checks remain.
