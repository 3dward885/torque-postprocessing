2. IMPLEMENT THESE SIX CHANGES

A. Clarify the two temperature fields

Rename:
  Temperature setpoints (K) → Temperatures in this file (K)
  Temperature setpoint (K) → Override selected scan temperature (K)

The general list supplies experimental temperatures for the file. Each scan
must match exactly one supplied temperature within the configured deviation,
unless it has an explicit selected-scan assignment.
The override applies only to the selected scan(s); a blank override preserves
existing explicit assignments. Keep units, precedence, save/load and matching
behavior unchanged. Explain the two scopes briefly in help.

B. Accept spaces and commas in temperature lists

Use one small shared GUI/CLI parser for whitespace-separated, comma-separated
and mixed lists. These inputs must produce equivalent settings:
  2.5 5 10 25 50 100 150 200 250
  2.5, 5, 10, 25, 50, 100, 150, 200, 250

Support arbitrary finite noninteger values and retain Decimal token semantics.
Keep existing malformed/nonfinite/duplicate-value checks and missing/ambiguous
assignment handling. Preserve the existing list representation in saved settings.
Add a short input hint, such as “Separate values with spaces or commas”.
Document quoting for whitespace lists in the CLI.

Do not hardcode experimental targets, infer a temperature grid, widen tolerances
or alter the inclusive absolute-deviation comparison. The example temperatures
are user-provided experiment settings, not production defaults.

C. Synchronize the View selector with the actual plot

Fix the state in which View says Corrected while the graph shows raw torque
because processing has not run or settings have invalidated the result.

Whenever raw measurements are plotted, show Raw in the selector. Only make a
processed view available when the selected scan has a valid corresponding result.
Handle initial import, signal/background selection, file/scan switching,
settings changes, partial processing, failures and successful reprocessing.
Retain the selected view when it remains valid; otherwise use an honest fallback.

Changing View must only change visualization. Save treated data must continue
to export committed corrected torque regardless of the displayed view.
Preserve invalidation/export safeguards and avoid displaying stale previews.

D. Hide the activity bar when idle

Start with the activity bar hidden. Show and animate it only while an existing
background task is running, including loading, processing and saving.
Stop/reset and hide it on completion or failure, and on cancellation if already
supported. Avoid toolbar movement and lingering animation callbacks on closure.

Retain useful status text. The bar indicates activity, not a percentage complete.
Do not introduce a fabricated completion estimate or a new task framework.

E. Add brief hover help after 1 second

Show contextual help after 1000 ms over a control or its labelled option area.
The accepted 1-second delay replaces the earlier 5-second proposal.

Keep help visible while the pointer remains over its control or the tooltip,
without an automatic reading timeout. Dismiss when the pointer leaves both,
on Esc, on interaction or when the containing window closes.
Esc must not immediately reopen the tooltip under a stationary pointer or also
close the parent dialog. Cancel pending timers when targets disappear.

Do not take focus, modify settings or obstruct normal interaction. Use Tk event
scheduling, not blocking sleeps. Cover exposed controls in the main window,
acquisition settings including expanded controls, background/extrapolation,
plot views and manual zero adjustment. Include disabled actions and explain
what enables them. Menus must have equivalent explanations in Help.

Explain purpose, units, scope and accepted input syntax where relevant. Keep
tooltips short, with detailed instructions/examples in Help. Help must also be
accessible without hovering.
