3. NUMERICAL CONTRACT AND SCIENTIFIC LIMITS

VERIFIED recipe retained: six significant digits from original signal and background torque tokens; unweighted degree-six polynomial versus nominal angle, scaled domain [0,200] degrees; background subtraction; centering; binary64 .8g formatting of D; exact Decimal multiplication of exported D for E. The imported legacy code sets Decimal precision to 50. Preserve those numerical semantics if extracting functions into an independent application core. Significant digits are not decimal places. Add no intermediate rounding.

For one acquired signal pass, using every actual retained sample:
  u_i = rounded_signal_i - evaluated_background_i
  c_mid = (min(u) + max(u)) / 2
  c_final = c_mid + delta
  tau_i = u_i - c_final

All three offsets and u/tau are in N m. Positive delta moves the final curve downward. At delta=0, max(tau) = -min(tau) = (max(u)-min(u))/2 before serialization, within floating-point error. A nonzero manual delta generally changes that equality. Do not recenter afterward. The signed imbalance displayed is max(tau)+min(tau), in N m.

DERIVED quantities: extrema, midrange, accepted numerical offset, corrected values and imbalance. FITTED quantities: background polynomial coefficients. PROVIDED: the user's desired balancing criterion and any manual choice. Neither a numerical balance nor a user choice establishes a measured calibration constant or physical drift.

Take extrema over the complete acquired pass, even after zooming or when an angle is missing. Preserve the supported changing-field pass as one acquisition. Do not infer absent measurements or evaluate interpolated signal extrema. A constant-valued valid pass centers to zero at delta=0; show zero range and omit range-normalized diagnostics rather than divide by zero. Empty/nonfinite data remain errors.

A vertical translation preserves sample angles, extrema locations, point-to-point differences and peak-to-peak torque before serialization. It does not enforce angular antisymmetry, equal lobe areas, or common amplitudes across fields/temperatures. Noise can influence sampled extrema; do not add smoothing, point rejection, robust estimators, normalization, angular shifts or simulation matching.

D remains torque in N m; E remains labelled N m/mol. Use the explicitly configured factor only after D is exported. The factors 911.63 and 1575.45 reproduce reference arithmetic; their physical normalization remains unverified. Keep baseline entry in N m even if the existing application offers a separate molar preview. No sample metadata or calibration-file interpretation is needed to design this option. No investigation of the known Rot2 50 K endpoint is included.

4. CHECKBOX, EDITOR AND STATE TRANSITIONS

PROPOSED control: "Interactive baseline adjustment", unchecked for new sessions. It controls review mode for the run; accepted overrides are independent for each signal pass. Off means the ordinary policy remains active, not that all centering is disabled. An unreviewed pass keeps its ordinary policy even while review mode is on.

State consists of: run-level enabled flag; selected pass; optional accepted record per pass; optional draft for the selected pass; and whether the draft differs from its accepted/initial value. Preview and committed export are distinct. Show effective method per pass: ordinary policy, accepted midrange, manual offset, inactive override, or stale override.

The upstream fingerprint covers raw bytes, pass membership/angles, background association, quantization, polynomial degree/basis/domain/weights, subtraction order and relevant numerical implementation/environment. Use deterministic JSON for its structured settings and defined little-endian binary64 bytes plus length for u. Exclude display zoom/style, timestamps and the manual values themselves. Do not use the hash of the entire mutable configuration as this fingerprint: editing an override would otherwise invalidate itself.

Changes to raw bytes, segmentation, background association or upstream arithmetic invalidate affected offsets. A zoom/font change does not. Changing ordinary centering preserves the same u and accepted offset but changes the recorded underlying policy; recompute output status. Changing the explicit molar factor invalidates E/export, not the N m baseline. Revalidate against the recomputed u on load and before headless export.

Canonical replay uses c_final_binary64_hex directly. Check that stored c_mid agrees with current calculation and that the saved delta/c_mid relation produces the same canonical final offset. Reject inconsistent or nonfinite redundant fields; do not guess which is correct. Display may use fewer digits, while editable/saved values retain round-trip precision. Store only accepted overrides, not an event-by-event drag log or synthetic background samples.

Headless processing reads raw inputs and configuration only. Both profile routes must honor the feature block; an unsupported version or unknown pass key must produce an explicit error instead of ignoring it. Disabled overrides may remain inactive even when stale, and must never affect outputs. When re-enabled they require validation. Record active/inactive/stale status and the reason in provenance.

Extend the existing output provenance/row ledger with effective method and c_final per pass, linking rows to the accepted record. Preserve source hashes, relevant code/config hashes, output hashes, background metadata and factor provenance. Use new output paths; do not overwrite raw sources or frozen reference artifacts. Keep reference loading in the independent validator. No hidden reference-selected lookup or production import of diagnostic tables is permitted.
